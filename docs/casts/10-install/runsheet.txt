This is the only cast with nothing beside this runsheet, so rec.sh records in a throwaway
scratch dir instead of a fixture dir — it prints the path as `scratch dir: ...` before it
hands over. That is right: this cast *is* `uv add` into an empty project, and there is no
fixture to commit. It is also the only cast that touches the network (PyPI, one resolve).

Read all five notes before the first take. Three of them are the difference between a
usable recording and a retake.

1. WARM THE UV CACHE FIRST. Do a full dry run — rec.sh, all six lines, Ctrl-D — and then
   rerun rec.sh and record the second one. On a cold cache `uv add` adds download progress
   lines (`Downloading pydantic-ai-slim (1.1MiB)`) that are not in the transcript below.
   Two consecutive warm takes came out byte-identical except for the `in 49ms` / `in 17ms`
   timings and pytest's `in 0.01s`.

2. `unset VIRTUAL_ENV` is line 1 and it is not optional. rec.sh sources the repo's venv off
   camera so the last line can be a bare `pytest`, and uv sees that as an active environment
   that is not this project's. Left set, `uv add` opens with:

     warning: `VIRTUAL_ENV=/Users/…/docs-why-asciinema/.venv` does not match the project
     environment path `.venv` and will be ignored; use `--active` to target the active
     environment instead

   which puts the recorder's own absolute path on screen and advises a flag that would
   install PyPI 0.3.0 straight over the repo's editable install and break every other
   cast. Do not take that advice. If rec.sh is ever changed to unset VIRTUAL_ENV itself,
   delete line 1 from this runsheet and re-record.

3. `uv init` is on camera. It has to be — rec.sh creates the scratch dir empty and starts
   recording in the same breath, so there is no off-camera window to use. It reads better
   there anyway: `uv add` needs a project to add to, and one visible line that creates the
   pyproject.toml is honest, where a pyproject.toml the reader never saw appear is not.
   Lines 3–6 are then the page's four commands, verbatim.

4. Nothing keeps .pytest_cache out of this run, and nothing needs to: rec.sh exports
   PYTEST_ADDOPTS='-p no:cacheprovider' for every cast so the flag never appears on
   camera, and here the directory is scratch and gets deleted on the next launch anyway.
   The pytest line is therefore the page's fourth command, character for character.

5. The version numbers are the one part of this cast that is not reproducible. `uv init`
   pins requires-python from whatever CPython the recorder has, the resolve comes from
   PyPI on the day, and pytest-agent-eval's own `pydantic-ai` dependency drags in ~100
   packages whose versions move weekly. Do not chase the numbers below. Whoever publishes
   the cast must re-transcribe the collapsed transcript from the take that was actually
   uploaded, not copy the one that shipped with this runsheet.
