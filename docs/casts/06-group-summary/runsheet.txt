06-group-summary — replaces the console block in docs/why/gates.md

  start:   docs/casts/rec.sh 06-group-summary
  window:  80x24 (set for you)

The point of this take is the last five lines: a group whose 90% threshold absorbs a
real failure, a must_pass pin that individually passed, and an exit code of 0 with the
failure still on screen. `pytest` itself exits 1 here — the plugin overrides it.

Four lines. Two facts to watch, because they are the two the page asserts:
  * `booking: 9/10 passed (90%)` — this is why evals/ holds ten gate:booking
    transcripts. Nine, or eleven, and the figure's "9 / 10 = 90%" stops being true.
  * `smoke: 4/4` with ONE space after the colon. groups.py never pads group names.
    An earlier hand-written version of this block aligned them; it was wrong.

Everything on screen is deterministic except the `in 0.0Ns` duration.

TYPE:
  bat pyproject.toml
      -> the two group tables gates.md quotes, then [tool.pytest.ini_options]
      -> [tool.agent_eval.groups.booking] threshold = 0.9 / tags / must_pass
      -> [tool.agent_eval.groups.smoke]   tags = ["smoke"]
      -> if a [project] table scrolls past, you are not in the cast directory

  ls evals/
      -> 14 files in three columns: ten booking transcripts, four smoke ones
      -> confirmation.yaml is the must_pass pin, edge_case.yaml is the failure
      -> if anything other than *.yaml shows up (README, __pycache__), Ctrl-D,
      ->    `git status` this directory, rerun rec.sh

  pytest --agent-eval-live -q
      -> .F............                                                           [100%]
      -> one F, in second position — that is evals/edge_case.yaml
      -> ================================ group summary =================================
      -> booking: 9/10 passed (90%) >= 90% required -- PASSED
      ->   failures: booking_edge_case
      ->   must_pass: booking_confirmation ok
      -> smoke: 4/4 passed (100%) >= 100% required -- PASSED
      -> exit code overridden to 0: all group thresholds met
      -> 1 failed, 13 passed in 0.0Ns
      -> if it says "14 skipped" and "live mode is off", --agent-eval-live did not
      ->    make it onto the line, and both groups print SKIPPED instead of a rate.
      ->    Ctrl-D and rerun rec.sh
      -> if it says "no tests ran" / "collected 0 items", pytest read the REPO
      ->    pyproject.toml instead of this cast's. Ctrl-D and rerun rec.sh
      -> if booking shows anything but 9/10, or smoke anything but 4/4, the evals/
      ->    directory has drifted. Ctrl-D, `git status` this directory, rerun rec.sh
      -> if it says "must_pass: booking_confirmation FAILED", the group FAILS and the
      ->    override never happens — the next line would print 1. Ctrl-D and rerun

  echo $?
      -> 0
      -> this is the whole point of the page. If it prints 1, the override did not
      ->    fire: re-read the group summary above for a FAILED group. Ctrl-D and rerun

  Ctrl-D

THEN:
  docs/casts/upload.sh 06-group-summary
  paste the printed data-cast-id="..." into docs/why/gates.md
